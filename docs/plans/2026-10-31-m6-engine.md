# M6 — Engine & results Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `semantic-sec analyze` work end to end: map → candidates → payloads → cache → LLM → grounded findings → suppressions, fingerprints, dedup, baseline, filters → a summary and the right exit code.

**Architecture:**
- An `Engine` takes an `AnalysisPipeline` result (candidates and payloads) and runs the M5 layer: `ClientFactory::validated()` over a `RequestPool`, with a `ResultCache` in front.
- Each answer is grounded with `GroundingChecker::ground()`, then turned into `Vulnerability` objects and post-processed per SPEC §11.
- `AnalyzeCommand` turns the resulting `AnalysisResult` into minimal console output and an exit code.
- Rich console, JSON and SARIF formatters and baseline file IO are M7.

**Tech Stack:** PHP ^8.2, nikic/php-parser 5 (`PrettyPrinter\Standard`), Guzzle (M5), symfony/console.

**Spec:** `docs/SPEC.md` §6, §7, §11, §12, §13, §16. Roadmap tasks 34–37, plus the two user decisions below.

## Decisions (user, 2026-10-31)

1. **`authorization_middleware`** config list is in M6.
   - A route behind a listed middleware has an **Authorization**-strength check, so it stops being a `missing_authorization` candidate.
   - It does **not** cover any route parameter (`covers = null`, route-wide), so `idor` is still selected wherever the selector needs the identifier covered.
   - The motivating case is a custom permission middleware such as `permission:manage`.
2. **The budget is a hard cap.**
   - Before each dispatch, the pool reserves `2 × (estimate(system . user) + maxTokens)`. The factor 2 covers the one schema retry.
   - It dispatches only if `used + reserved + thatReservation ≤ budget`.
   - On settle, the reservation is released and the actual tokens are added.
   - SPEC §12 is reworded: no overshoot, except for HTTP attempts the provider never bills.

## Decisions (controller, from M5 deferrals)

3. **Payloads with no tagged code** (the "source not available" ones) are never sent. They're counted in `AnalysisResult::$skipped` with a warning.
4. **"Every request failed" means exit 2.** It applies when at least one request was attempted and none produced an `Ok` answer from either the cache or the provider. Refused, truncated and invalid answers count as failed for this rule.
5. **The cache key uses the requested model, not the one that answered.** Only `Ok`, validated answers are cached. Refused, truncated, invalid and failed requests are never cached.
6. **Multi-request cassettes replay by request body.** Concurrency makes order nondeterministic. In `body` mode, `CassetteHandler` matches the sha256 of the scrubbed request body plus method and URI, and order no longer matters.
7. **Output in M6 is minimal.** It prints one line per reported finding plus a summary block to stdout. `--format`, `--output`, `--baseline`, `--generate-baseline` and `--since` stay for M7; the command rejects them with `available in a later release` and exit 2. Same for `--format` values other than `console`.

## Global Constraints

- PHP `^8.2`. CI runs 8.2/8.3/8.4 at the lowest and highest dependency versions.
- Never disable Composer security-advisory blocking. Never install Laravel 10/11.
- There's no host PHP; use `docker compose run --rm php <cmd>`.
- The default suite makes zero network calls. **Never open `.env.live`.** Live runs are controller-only and need the user's OK when they cost more than a few cents.
- Real apps are read-only. Anything that writes `<root>/.semantic-sec/` runs on a scratch copy.
- The `.semantic-sec/` output-dir guard from M4 (no symlinks, no escaping the root) applies to every write: dry-run, cache.
- A false exclusion or a false drop hides a vulnerability, which is the worst failure. Never add a rule that drops a grounded finding without a SPEC basis.
- One-line comments only. Commit as Tushar Khan with no AI trailer. One branch, `m6-engine`, and one PR into `main`.

## Review Focus

1. **Fingerprint stability.** Editing whitespace, comments or another method must not change a fingerprint; a code change inside the symbol must. Re-attributed symbols (`gate:…`, closure ids) need a stable fallback hash. Tested in Task 2.
2. **Cache poisoning or staleness.** Changing middleware, a policy, the model, the prompt version or a ruleset must miss the cache. A corrupt or truncated cache file must be ignored with a warning, never crash, never yield findings. Tested in Task 3.
3. **Budget at the boundary.** A budget smaller than one reservation dispatches nothing and reports `budgetExceeded`. The hard cap holds with concurrency 5 and schema retries. Tested in Task 4.
4. **Suppression edge cases.** An `all` suppression, a category versus CWE suppression, a suppression in a different file from the finding, and a reason-less suppression (honoured, warned). Tested in Task 5.
5. **Exit-code precedence.** 1 beats 3. All-failed gives 2, but only when nothing succeeded. Low-confidence-only findings give 0. A missing key gives 2 with the env var name, never the value. Tested in Task 6.

### Task 2: `Vulnerability`, `Fingerprinter`, dedup

**Files:**
- Create: `src/Engine/Vulnerability.php`, `src/Engine/Fingerprinter.php`, `src/Engine/Deduplicator.php`
- Test: `tests/Unit/Engine/{FingerprinterTest,DeduplicatorTest,VulnerabilityTest}.php`

**Interfaces (produced):**
- `final readonly class Vulnerability` holds:
  - `Category $category`, `Severity $severity`, `Confidence $confidence`
  - `string $title`, `string $file`, `int $line`, `string $symbol`
  - `string $context`, `string $flaw`, `string $fix`, `string $patch`
  - `list<array{file:string,line:int,symbol:string}> $path`
  - `string $routeKey`, `string $payloadId`, `string $model`, `string $fingerprint`

  It has a static `fromGrounded(array $finding, Payload $p, string $model, string $fingerprint): self`.
- `Fingerprinter(ParseResult $parsed, SymbolTable $symbols)`
  - `fingerprint(string $file, string $symbol, Category $c, Payload $p): string` returns `sha256(file|symbol|CWE|normalisedHash)`.
  - `normalisedHash` is the sha256 of `PrettyPrinter\Standard` output for the symbol's node (method, property statement or class) with comments removed. Never mutate the shared AST; clone or print with comments stripped.
  - A symbol with no AST node (`gate:…`, closure ids, unknown) falls back to the sha256 of that header's tagged line texts in `$p->code`, with `L<n>| ` prefixes and `//` and `/* */` comments stripped and whitespace collapsed.
  - The CWE comes from `Category::cweId()`.
- `Deduplicator::merge(list<Vulnerability>): list<Vulnerability>`. For each fingerprint it keeps the highest severity, then the highest confidence, and merges the paths uniquely in order.

**Interfaces:**
- `ResultCache(string $dir, string $provider, string $model, list<CustomRuleset> $rulesets, bool $readEnabled)`
  - `key(Payload $p): string` is `sha256(Application::VERSION | provider | model | SecurityPrompt::VERSION | rulesetHash | $p->text())`, where `rulesetHash` is the sha256 of the JSON of `[name, prompt]` pairs.

### Task 4: Hard budget cap

### Task 5: `Engine` and `AnalysisResult`

**Files:**
- Create: `src/Engine/Engine.php`, `src/Engine/AnalysisResult.php`, `src/Engine/Baseline.php`
- Modify: `src/Llm/Http/CassetteHandler.php` (adds `body` match mode, decision 6)

  - `tests/Integration/Engine/BenchmarkEngineTest.php`, which replays a body-matched cassette when one exists and otherwise uses a scripted fake
  - `tests/Unit/Llm/Http/CassetteHandlerTest.php`

**Interfaces:**
- `Baseline` holds a set of fingerprints, with `Baseline::empty()`, `Baseline::of(list<string>)` and `contains(string): bool`. File IO is M7.
- `AnalysisResult` holds:
  - `list<array{vulnerability: Vulnerability, failing: bool}> $findings`
  - `list<array{vulnerability: Vulnerability, suppression: Suppression}> $suppressed`
  - `list<Vulnerability> $baselined`
  - `list<string> $warnings`
  - `array{candidates:int, payloads:int, skipped:int, unsent:int, sent:int, cacheHits:int, ok:int, refused:int, truncated:int, invalid:int, failed:int, dropped:int, filtered:int, tokens:int, budgetExceeded:bool} $stats` (`unsent`: stopped by the budget; `filtered`: below `level`)
- `Engine(ClientInterface $client, ResultCache $cache, Fingerprinter $fp, GroundingChecker $g, ParseResult $parsed, Config $config, Baseline $baseline)`, with `run(list<Payload> $payloads, int $candidates): AnalysisResult`.
  - Skip payloads with no `L<n>|` tag (decision 3).
  - Cache hits come from `get()`. Misses go through `RequestPool` using `ClientFactory::request()`. Ok responses go to `put()`.
  - Each finding goes through `ground()`. A dropped finding counts in `dropped` and adds one warning per reason kind.
  - Build the `Vulnerability` with `Fingerprinter`, then apply suppressions: the `SuppressionSet` of the finding's file, `find(line, category)`; a reason-less suppression is honoured with a warning.
  - Then `Deduplicator`, then baseline, then filters: drop anything with severity below `level`, and mark `failing = confidence ≥ minConfidence`.
  - Warnings carry every pool failure (payload id plus message), cache warnings and invalid outcomes.
- `CassetteHandler` gets a `match: 'order'|'body'` parameter, defaulting to `order`. In `body` mode, replay finds the interaction whose scrubbed request body sha256, method and URI match, regardless of order. Each interaction is used once, and `assertExhausted()` still applies.
