# M5 — LLM layer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Send M4 payloads to Anthropic, OpenAI-compatible (OpenAI, Groq) or Ollama models and get back schema-valid, grounded findings. The layer is concurrent, retried, budget-capped and fully testable offline.

**Architecture:**
- Each provider client turns an `LlmRequest` into one raw HTTP call through a shared Guzzle stack. The stack carries retry middleware and a cassette handler.
- Each client resolves a promise to an `LlmResponse`.
- `RequestPool` runs clients with bounded concurrency and a token budget.
- `ValidatingClient` adds the one schema retry.
- `GroundingChecker` drops findings not anchored in the payload.

The engine that wires this into `analyze`, plus caching and fingerprints, is M6.

**Tech Stack:**
- PHP ^8.2
- `guzzlehttp/guzzle` ^7.9 (new)
- `opis/json-schema` ^2.4 (new)
- PHPUnit 11 with Guzzle `MockHandler`

**Spec:** `docs/SPEC.md` §10 (LLM layer) and §12 (budget). The roadmap is `docs/plans/2026-10-28-roadmap.md` (M5, tasks 27–33).

## Decisions taken while planning (SPEC §10 is updated in Task 2)

Provider API facts were refreshed on 2026-10-31: Anthropic through the `claude-api` skill, plus the Groq and OpenAI docs.

1. **Anthropic does not use a forced tool.** `tool_choice: {type: tool}` returns 400 on `claude-opus-5-5` and the other current models. Use structured outputs instead: `output_config.format = {type: "json_schema", schema: …}`. Read the first `text` block and JSON-decode it.
2. **No `temperature` for Anthropic.** On `anthropic-version: 2026-10-21` any sampling parameter returns 400. OpenAI and Ollama send `temperature` only when config sets it, and OpenAI sends `seed` only when config sets it (reasoning models reject it).
3. **Raw HTTP over Guzzle for all three providers, not vendor SDKs.** This is SPEC §10's design: one promise pool, one retry middleware and one budget for every provider. The Anthropic request shape is the documented REST shape. Headers: `x-api-key`, `anthropic-version: 2026-10-21`, `content-type: application/json`.
4. **Refusals.**
   - Anthropic requests to `https://api.anthropic.com` send `fallbacks: "default"` with the header `anthropic-beta: server-side-fallback-2026-07-01`. A security scanner can trip the `cyber` classifier, and `default` routes those refusals to another model server-side. Custom `base_url`s omit both, since proxies may reject them.
   - `stop_reason: "refusal"` (Anthropic) or a non-null `message.refusal` (OpenAI) becomes `LlmOutcome::Refused`. That is never a crash and never retried.
5. **Groq is not a fourth provider.** It is `provider: openai`, `base_url: https://api.groq.com/openai/v1`, `api_key_env: GROQ_API_KEY`, `model: openai/gpt-oss-120b`, and it supports strict `json_schema`. README documents it as a recipe.
6. **Default models live in `config/defaults.php`**, never in docs:
   - anthropic: `claude-opus-5-5`
   - openai: `gpt-6-astra`
   - ollama: none, so config must name one. Exit 2 otherwise: `ollama needs a model in semantic-sec.yaml`.
7. **Anthropic effort** comes from a new config key `effort` (`low|medium|high|xhigh|max`, default `high`), sent as `output_config.effort`. Thinking is left at the model default (adaptive, always on for Opus 5.5).
8. **Prompt caching (Anthropic):** the system prompt is one text block with `cache_control: {type: "ephemeral"}`. It is identical for every request in a run.
9. **Framework notes move out of the payload into the system prompt** (an M4 deferral). `PayloadBuilder` stops emitting `Framework notes:`. `SecurityPrompt::system()` appends `FrameworkContext::promptContext()` once.
10. **The schema sent to providers is strict-mode-safe:** every property is `required`, every object has `additionalProperties: false`, there's no recursion, and there are no `maxLength`/`minimum` constraints (Anthropic rejects those). `title ≤ 120` and `line ≥ 1` are checked client-side by `ResponseValidator`.

## Global Constraints

- PHP `^8.2`. CI runs 8.2/8.3/8.4 at lowest and highest deps.
- Never disable Composer security-advisory blocking. Never install Laravel 10/11; real-app checks use Laravel 12 apps only, read-only.
- There is no host PHP. Every command runs as `docker compose run --rm php <cmd>` from the repo root.
- The default test suite makes **zero** network calls. Live tests run only with `SEMANTIC_SEC_LIVE=1`.
- API keys are read only from env, or from the env var named by `api_key_env`. They are never printed, logged, put in an exception message or written to a cassette. Cassettes scrub the `x-api-key`, `authorization` and `api-key` headers.
- Live and record runs load keys from a git-ignored `.env.live` in the repo root, parsed by the live-test bootstrap. Add `.env.live` to `.gitignore` in Task 1.
- One-line code comments only. Never edit `benchmark/`.
- Commit as Tushar Khan with no AI trailer. Use one branch, `m5-llm-layer`, and one PR into `main` at the end.

## Review Focus

1. **Model output wrapped in a Markdown fence or surrounded by prose** (Ollama, or Groq's best-effort path). Decoding accepts exactly one ```` ```json … ``` ```` fence around the object. Anything else is `Invalid` and gets the one schema retry. Test in Task 5.
2. **401/403, or a missing key.** It fails at once with `"<provider> rejected the API key (HTTP 401)"` or `"<ENV_NAME> is not set"`, with no retry, and the key value never appears. Test in Task 3, Task 4 and Task 6.
3. **`Retry-After` given as seconds or as an HTTP-date, and a 429 storm.** Backoff honours both forms, caps at 4 attempts, then rejects with the last status. Test in Task 6.
4. **`stop_reason: "max_tokens"`, meaning truncated JSON.** It becomes `LlmOutcome::Truncated`, not a decode crash, and is not schema-retried. Test in Task 3.
5. **A finding that cites a file or line from another part of a split payload, or a line inside a redacted line.** It is dropped with reason `line L<n> not in payload` and no crash. Test in Task 7.

- `final readonly class LlmRequest(string $payloadId, string $system, string $user, array $schema, string $model, int $maxTokens = 16000, ?string $effort = null)`, plus `withUserSuffix(string $s): self`, which returns a copy with `$s` appended to `user`.

  - `replay` serves interactions in order. It asserts that each method and URI match, and on a mismatch or when interactions run out it throws `\LogicException("cassette <path>: expected <m> <uri>, got …")`.
  - `record` forwards to a real handler, appends the interaction with auth headers scrubbed, and saves.

### Task 6: RequestPool, retries and budget

**Files:**
- Create: `src/Llm/RequestPool.php`, `src/Llm/PoolResult.php`, `src/Llm/Http/RetryMiddleware.php`, `src/Llm/ClientFactory.php` (builds the configured provider client from `Config` and env)
- Test: `tests/Unit/Llm/RequestPoolTest.php`, `tests/Unit/Llm/Http/RetryMiddlewareTest.php`, `tests/Unit/Llm/ClientFactoryTest.php`

**Interfaces:**
- `RetryMiddleware::create(callable $sleep = null): callable`. It wraps Guzzle `Middleware::retry`.
  - Retry on 429, any 5xx, and connection errors. 401, 403, 400 and 404 never retry.
  - At most 4 attempts.
  - The delay is `1000 * 2^(n-1)` ms, unless `Retry-After` is present (seconds, or an HTTP-date) and longer.
  - `$sleep` is injectable so tests take no wall time.
- `ClientFactory::create(Config $c, ?callable $handler = null): ClientInterface`.
  - It resolves the key from `api_key_env`, or else `ANTHROPIC_API_KEY`/`OPENAI_API_KEY`. A missing key throws `ConfigException("<ENV> is not set")`.
  - It resolves the model from `$c->model`, or else `config/defaults.php`.
- `RequestPool(ClientInterface $client, int $concurrency, ?int $budgetTokens)` and `run(iterable<LlmRequest> $requests): PoolResult`, where `PoolResult(list<LlmResponse> $responses, list<array{payloadId: string, error: string}> $failures, int $usedTokens, bool $budgetExceeded)`. It uses `GuzzleHttp\Promise\Each::ofLimit`.
  - Before each dispatch, if `usedTokens + TokenEstimator::estimate(system . user) > budgetTokens`, it stops dispatching (in-flight requests finish) and sets `budgetExceeded`.

### Task 7: Response validation and grounding

**Files:**
- Create: `src/Llm/ResponseValidator.php`, `src/Llm/ValidatingClient.php`, `src/Llm/GroundingChecker.php`
- Test: `tests/Unit/Llm/ResponseValidatorTest.php`, `tests/Unit/Llm/ValidatingClientTest.php`, `tests/Unit/Llm/GroundingCheckerTest.php`

**Interfaces:**
- `ResponseValidator::errors(array $data): list<string>`. It returns the `opis/json-schema` errors against `FindingSchema::schema()`, plus the client-side rules: `title` must be 120 chars or fewer, and `line` and every `path[].line` must be ≥ 1.
- `ValidatingClient(ClientInterface $inner)` implements `ClientInterface`.
  - On an `Ok` response with errors, it re-sends once using `withUserSuffix("\n\nYour previous answer was invalid: <errors>. Answer again with valid JSON.")`.
  - If the second answer is still invalid, it resolves to `Invalid` with the errors in `detail`.
  - Tokens from both attempts are summed.
  - `Invalid` from the inner client (bad JSON) also gets the one retry. `Refused` and `Truncated` never retry.
- `GroundingChecker(SymbolTable $symbols)` with `check(array $finding, Payload $payload): ?string`. It returns null when the finding is grounded, otherwise one of these drop reasons:
  - `file <f> not in payload`
  - `line L<n> not in payload`
  - `line <n> outside <symbol>`
  - `path step <i> not in payload`

  It parses `// FILE: <path> :: … (La-Lb)` headers and `L<n>|` tags out of `$payload->code`. For `Class::method`, the span comes from `findMethod`. For `Class::$prop`, it comes from `findProperty`, and the line must equal the property's line. For `Class`, it comes from `getClass`. A symbol the table doesn't know gives a pass on the span check only.
