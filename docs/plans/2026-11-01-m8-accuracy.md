# M8 — Accuracy gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Measure semantic-sec honestly against the SPEC §15 release gate, on the existing corpus plus a new **blind** corpus. Compare it with Anthropic's `claude-code-security-review` on the same code, and stop at a written decision report for the user.

**Architecture:**
- A new benchmark app, `benchmark/laravel12-app`, holds about 10 blind vulnerable/safe pairs. A separate agent writes them without reading the scanner's source. Each pair is proven by real Laravel 12 feature tests in `benchmark/verify`.
- A dev-only scorer, `bin/benchmark`, runs `analyze --format json --level low` on each app. Live runs are recorded to body-mode cassettes; otherwise it replays them. It scores the results against `expected.yaml` and writes `docs/benchmark-results.md`.
- The competitor runs in a separate Python container against a PR in a private scratch repo. A converter maps its findings into the same scorer.

**Tech Stack:**
- PHP ^8.2, the existing semantic-sec pipeline, PHPUnit
- Docker
- a Python 3.11 container for the competitor
- `gh` CLI

**Spec:** `docs/SPEC.md` §15 (gate and competitive check). Roadmap M8, tasks 43–45.

## Decisions (user, 2026-11-01)

1. **Blind corpus.** About 10 new pairs, written by an agent that may read only `benchmark/` (the README, `expected.yaml` and the existing apps, for format) and SPEC §3. It must **not** read `src/`, `docs/plans/`, the SPEC sections on the selector, payload or prompt, or the scanner's tests.
   - It covers patterns the existing corpus lacks:
     - a route behind custom authorization middleware only
     - nested resources (`/teams/{team}/projects/{project}`) with missing scope binding
     - team or tenant scoping
     - soft deletes / `withTrashed`
     - polymorphic relations
     - an update through a relation the user doesn't own
     - a policy method that checks the wrong attribute
     - a mass assignment via `fill()` plus `forceFill`
     - a state transition through a service
     - an IDOR through a query-string id on a list endpoint

     It also adds at least one **public-by-design** route.
   - Results are reported **separately** for `existing` and `blind`.
2. **Competitor.** It runs on a private scratch repo `tusharkhan/semantic-sec-bench`. Its `main` branch holds a minimal Laravel 12 skeleton README only. One PR adds the three benchmark apps' source.
   - Run Anthropic's `claudecode.evals.run owner/repo#N` locally in a Python container, with model `claude-opus-5-5` for parity if the tool allows an override. Otherwise use its default and say so.
   - Keys come from `.env.live` via `docker run --env-file .env.live`, never printed. `GITHUB_TOKEN` comes from `gh auth token`, passed as env and never printed.
   - Creating the repo, the PR and pushing to it is approved by the user for this purpose only.
3. **Budget cap $15** for all M8 live LLM calls, both tools together.
   - Estimate before every live run. Record actual tokens and $ in the ledger after it.
   - Stop and ask before any run that would cross the cap.
   - Price: claude-opus-5-5 at $4/M input, $20/M output, $0.20/M cache reads.
4. **Scoring rules (SPEC §15).**
   - A vulnerable case counts **found** when a finding with the case's category sits in the case's file (or the files the case lists in `accept`) at the case's symbol or an `accept`ed symbol.
   - A safe case is **flagged** when any finding of any category lands on its symbol.
   - Public-by-design routes must have **0** findings on their symbol.
   - The `map` check compares each case's `map:` list with `semantic-sec map --format=json` and requires 100%.
   - Suppressed findings count as found for the `suppressed: true` case and as not-flagged for everything else.
   - Findings below `--min-confidence` still count (`--level low`, all confidences), and the report also shows the high/medium-only numbers.
5. **Tuning is bounded.** If the gate fails, tune `SecurityPrompt` (bump `VERSION`) or selector rules. Every change is re-measured on **both** sets; a change that helps `existing` but hurts `blind` is rejected. The report lists every attempt and its numbers.

## Global Constraints

- PHP `^8.2`. Never install Laravel 10 or 11. Verification uses Laravel 12 only. Never disable Composer advisory blocking.
- There's no host PHP; use `docker compose run --rm php <cmd>`.
- **Never open or print `.env.live`.** Live runs are controller-only and logged against the cap.
- Existing corpus apps and `benchmark/expected.yaml` entries for them are edited only to fix a real bug that verification exposes. New cases go in the new app and new YAML entries.
- The default test suite stays offline. Replays use committed cassettes.
- One-line comments only. Commit as Tushar Khan with no AI trailer. Branch `m8-accuracy`, one PR into `main`, then **pause for the user's decision**.

## Review Focus

1. **Blindness.** Evidence that the blind cases weren't shaped by the scanner: the author's report lists the files it read. A reviewer checks that no case mirrors a scanner rule name or a test fixture.
2. **Ground truth.** Every blind vulnerable variant is exploitable and every safe one blocks the attacker while still working for its owner (verify tests pass in CI).
3. **Scorer correctness.** Hand-checked examples for found, missed, flagged, accepted alternate symbol, suppressed and public route. The scorer must not credit a finding on the wrong method of the right file.
4. **Fair comparison.** Same code, same model where possible, and the competitor's findings mapped to symbols by the same `SymbolTable`. State every asymmetry, e.g. the competitor sees a diff while we see the whole project.
5. **Cost honesty.** Every live run is logged with tokens and $, and the cap is respected.

### Task 7: List endpoints as IDOR candidates

- **Rule.** A route is selected for `idor` when all of these hold:
  - it's a GET route with no identifier
  - its execution path reads a **collection** of an Eloquent model (`get`, `all`, `paginate`, `cursor`, `chunk*`, `pluck`, `first*`, `simplePaginate`) that is **owned**
  - the query is **not** scoped to the auth user (§6 `query_scope`) and not covered by an Authorization-strength check

  A model counts as owned when it has a `belongsTo` to the auth user model, or a foreign key named `user_id`, `owner_id`, `team_id`, `tenant_id`, `organization_id` or `account_id` in `$fillable`/`$casts`/relations. **When unsure, select.**
- **Reason text:** `unscoped read of owned <Model> collection`.
- **Tests:** `idor-tenant-list-unscoped` (blind) vuln selected; its safe variant (two-hop scope) not selected. Existing gates stay 15/15 + 15/15.
- **Cost check:** report the real-app candidate and payload counts and the token delta before and after, read-only.

### Task 8: `scopeBindings()` as a query scope

### Task 9: General prompt guidance on authorization *content*

- Add a general instruction to `SecurityPrompt`: an authorization check counts only if it compares the user to the attribute that represents ownership or permission over **this** resource and action. A check against an unrelated attribute (creator vs. owner, the parent instead of the child, a role instead of ownership) is no protection.
- Bump `VERSION` to 3.
- **Honesty:** this guidance is informed by the blind case `idor-policy-wrong-attribute`, so that case is no longer blind for this pattern. The report marks it `tuned-on`.
