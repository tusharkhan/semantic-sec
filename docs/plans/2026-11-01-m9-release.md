# M9 — Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `tusharkhan/semantic-sec` **v0.1.0**:
- a PHAR attached to a GitHub release
- example CI files
- a complete README
- a clean public repository with rewritten history
- a Packagist listing, which the user submits

**Architecture:**
- **PHAR build:** Box builds a PHAR from `bin/semantic-sec`. A release workflow builds it on a `v*` tag and attaches the PHAR and its SHA-256 to the GitHub release.
- **CI examples:** `examples/` holds a GitHub Actions workflow (SARIF upload) and a GitLab CI job (GitLab SAST report). The GitLab job needs a small new formatter, `--format gitlab-sast`.
- **Publication:** the docs are scrubbed of private-app passages. The history is rewritten, then pushed to a **new** public repo, while the current repo is renamed and stays private as the archive.

**Tech Stack:** PHP ^8.2, humbug/box (run via Docker), GitHub Actions, git-filter-repo (Docker), `gh`.

**Spec:** `docs/SPEC.md` §17 (distribution) and §15 (the published comparison). Roadmap M9, tasks 46–48.

## Decisions (user, 2026-11-01)

1. **Version.** The first release is `v0.1.0`. `Application::VERSION` is `0.1.0`, and `-dev` is dropped on the tag commit.
2. **Visibility.** All release prep is done privately. The repo goes public only at the end, after a final scan, and **only after the user confirms again**.
3. **Packagist.** The user submits the package. Task 6 gives exact steps.
4. **Example CI.** It is proven by **one real run** on a private test repo. The user adds the `ANTHROPIC_API_KEY` secret; the controller never handles it. Cost is about $0.60, counted against the M8 cap. The test repo is deleted afterwards, with the user's OK.
5. **History is rewritten** with `git filter-repo`:
   - Both stray author emails (list them with `git log --format='%ae' | sort -u`) map to `Tushar Khan <tushar.khan0122@gmail.com>`.
   - `docs/plans/**` and `docs/benchmark-decision.md` are **removed from every historic commit**, then re-added once, scrubbed, in the final commit.
   - Commit messages naming the private app are reworded.
6. **Private-app passages are removed, not renamed.**
   - Every real-app result (names, routes, counts, findings) leaves the public docs. Benchmark numbers stay.
   - The README and SPEC example middleware becomes a generic `permission:manage`.
7. **The new public repo.** GitHub keeps every pull request's original commits reachable (`refs/pull/*`), and PR bodies quote private-app numbers. Force-pushing the existing repo therefore cannot clean it.
   - The rewritten history goes to a **new** public repo, `tusharkhan/semantic-sec`.
   - The current repo is renamed `tusharkhan/semantic-sec-private` and stays private, with its PRs, as the archive.
   - Renaming, creating and making public are each confirmed by the user right before they happen.

## Global Constraints

- PHP `^8.2` for the tool itself. The PHAR also serves projects on PHP 7.4–8.1, because it runs under the CI's PHP 8.2+ and only *reads* the project.
- Never disable Composer security-advisory blocking. Never install Laravel 10 or 11.
- There is no host PHP; use `docker compose run --rm php <cmd>`. Box and filter-repo also run in containers.
- **Never open `.env.live`.** No live LLM calls except the one example-CI run in Decision 4.
- One-line comments only. Commit as Tushar Khan with no AI trailer. Branch `m9-release`, one PR into `main` in the private repo, which the user merges.
- **Destructive or public steps are confirmed individually:** history rewrite, force-push, repo rename, repo creation, making public, tag push, and repo deletion.

## Review Focus

1. **The PHAR is self-contained.** It runs from any directory without the repo, finds `config/defaults.php`, and contains no `tests/`, `benchmark/`, `tools/`, `.env*`, cassettes or `docs/plans`. It works under the PHP 8.2 and 8.4 images.
2. **Nothing private ships.** Check the PHAR contents, the new repo's every commit, its commit messages and its README for the private-app name, its routes, the two stray emails, `.env.live`, any API key, and local paths (web-root and temp-dir checkouts).
3. **The examples actually work.** The GitHub workflow uploads SARIF and shows an alert. The GitLab report validates against GitLab's official SAST schema.
4. **The fresh install works.** `composer require --dev tusharkhan/semantic-sec` and `vendor/bin/semantic-sec map` succeed in a new Laravel 12 project.
