# semantic-sec — Roadmap to v1.0

**Spec:** `docs/SPEC.md` (authoritative). **Detailed plan for M0–M2:** `docs/plans/2026-10-28-m0-m2-foundation.md`.

## How this roadmap works

- **One milestone = one branch = one PR** on `github.com/tusharkhan/semantic-sec`. Work **pauses at every PR** for review before the next milestone starts.
- Each task below is roughly commit-sized and names its **check**: the command or test that proves it's done.
- **Detailed plans are written per milestone, just before it starts**, using the real interfaces of the code already merged. Only M0–M2 are detailed now; writing M3+ in full today would mean guessing at code that doesn't exist yet. The type names and namespaces in `SPEC.md` and the M0–M2 plan are binding on later milestones.
- After M3 we can optionally tag **v0.1.0** (the `map` command only: free, no API key). That gets real-world feedback on the authorization map before any LLM work.

| `Framework\Laravel\` | `LaravelContext`, `MiddlewareRegistry`, `RouteCollector`, `PolicyRegistry`, `AuthCheckExtractor`, `AuthorizationMap`, `RouteEntry`, `RouteParameter`, `AuthCheck`, `AuthCheckKind`, `AuthStrength` |

(The original spec's `Rulesets/` folder is folded into `Framework\`: a framework context *is* the ruleset.)
