# semantic-sec M2.5 (Benchmark Verification in Real Laravel) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove every `benchmark/expected.yaml` answer by running it. Each vulnerable variant must be exploitable, and each safe variant must block the attacker yet still work for its owner, inside a real Laravel 12 app. Every route key and its middleware must also match `php artisan route:list`.

**Architecture:** A throwaway Laravel 12 project is built on demand, inside Docker locally and in CI. Each benchmark app is overlaid onto it, together with verification-only files (migrations, factories, feature tests) kept in `benchmark/verify/<app>/`. Nothing from the real Laravel install is committed. The Laravel 10-style app runs on Laravel 12 through its legacy-structure support: an old-style `bootstrap/app.php`, with providers listed in `config/app.php`. A probe on 2026-10-30 confirmed this works: `route:list` showed `can:view,report` from constructor middleware and `can:view,note` from `authorizeResource`.

**Tech Stack:** `laravel/laravel ^12.0` skeleton, PHPUnit via `php artisan test`, SQLite in memory, Docker `php:8.2-cli` + Composer, GitHub Actions.

**Spec:** `docs/SPEC.md` §15 (benchmark is ground truth). User decision 2026-10-30: verify on Laravel 12 only. Do not install Laravel 10 or 11, and do not disable Composer's security-advisory blocking.

## Global Constraints

- **Never** install `laravel/framework` 10.x/11.x, and never set `COMPOSER_NO_SECURITY_BLOCKING`, `policy.advisories.block false` or `--no-security-blocking` (user decision).
- Skeleton: `composer create-project laravel/laravel:^12.0 <dir> --no-interaction --prefer-dist`.
- Everything new lives under `benchmark/verify/`. That path is already export-ignored and Pint-excluded, so nothing ships in the package.
- Corpus files (`benchmark/laravel11-app`, `benchmark/laravel10-app`) may be edited **only** to fix a real bug that verification exposes. Keep each variant's meaning, then re-run `vendor/bin/phpunit tests/Integration/Benchmark` (the line and integrity checks) and update `expected.yaml` lines if they moved. Each such fix is called out in the task report.
- Commands: `docker compose run --rm php <cmd>` from the repo root. The build runs in `/tmp` inside the container, so the repo is never polluted.
- The package's own checks stay green before each commit: phpunit, `phpstan analyse --memory-limit=512M`, `pint --test`.
- Commits are authored as Tushar Khan, with no AI trailer. Branch `m2.5-benchmark-verify`, one PR, then stop.
- Test vocabulary (exact meaning):
  - **exploited**: an authenticated attacker gets 2xx **and** the state change or data leak is asserted.
  - **blocked**: the authenticated attacker gets exactly the stated status (403, 404 or 422) **and** no state change.
  - **owner works**: the legitimate owner gets 2xx on the safe route.

## Review Focus

1. **A safe variant that is broken for everyone would pass "blocked" trivially.** Every safe test also asserts **owner works**. This is pinned in every case test (Tasks 2–5).
2. **A 302 redirect to login can look like protection.** Attackers are always authenticated (`actingAs`), and statuses are asserted exactly, never with `assertStatus(>=400)`. Pinned in the shared helper (Task 1).
3. **Laravel 12 may behave differently from the version a corpus app imitates.** The `route:list` middleware check (Task 6) pins the routing and middleware behaviour the static map relies on.
4. **Composer could start blocking Laravel 12 too.** `build.sh` must fail with a clear message naming the advisory problem, never silently. Pinned in Task 1 (`set -eu` plus an explicit message on a create-project failure).
5. **Leaking build artefacts into the repo.** `build.sh` refuses a target inside the repo. Pinned in Task 1.

### Task 3: Cases 8–11 (laravel11-app)

**Files:** Create `benchmark/verify/laravel11-app/tests/Feature/LogicCasesTest.php` and `benchmark/verify/laravel11-app/tests/Support/WakeupProbe.php` (namespace `Tests\Support`, autoloaded by the skeleton's `Tests\` PSR-4).

| Case | Vulnerable | Safe |
|---|---|---|
| 8 `mass-assign-guarded-empty` | B `PUT /vuln/account` with `name`, `is_admin=1`, `balance=999999`: exploited, B's account has `is_admin` true and the balance changed | `PUT /safe/account` with the same payload: 2xx, name changed, `is_admin`/extra fields **not** persisted (the "blocked" state here is "no effect" with a 2xx) |
| 9 `mass-assign-sensitive-fillable` | B `POST /vuln/teams` with `owner_id = A`: exploited, the team is owned by A | `POST /safe/workspaces` with `owner_id = A`: 2xx, the workspace owner is **B** |
| 10 `insecure-deserialization-cookie` | B `PUT /api/vuln/cart` with an **unencrypted** cookie `cart = serialize(new WakeupProbe())`: exploited, `WakeupProbe::$woken === true` | same cookie: `WakeupProbe::$woken === false` (2xx allowed) |

- `WakeupProbe` has `public static bool $woken = false; public function __wakeup(): void { self::$woken = true; }`. Reset it in `setUp`.
- Authenticate the api routes with `Sanctum::actingAs`.
- Send the cookie with `withUnencryptedCookie`. The `api` group doesn't encrypt cookies, which is exactly the exploit.

### Task 6: Route and middleware check against `route:list`

**Files:** Create `benchmark/verify/lib/check-routes.php` (plain PHP, run inside the built app via `php check-routes.php <expected.yaml> <app> <route-list.json>`). Modify `run.sh` to run `php artisan route:list --json > <tmp>` and then the checker.

**Rules (exact):**
- **Key match:** expected `"<METHOD> /<uri>"` matches a route:list entry when `METHOD` is in `explode('|', method)` and `ltrim(uri,'/')` equals the route:list `uri` after removing `:field` binding suffixes from both sides.
- Every expected route for this `<app>` (both variants of every case, plus `public_routes`) must match exactly one entry, or the check fails listing the misses.
- **Middleware implied by `map`:**
  - `authentication` in the map → middleware contains `auth`, `auth:<guard>`, or `Illuminate\Auth\Middleware\Authenticate`.
  - `route_ability` in the map → contains at least one `can:` entry.
  - Neither `route_ability` nor `controller_ability` in the map → **no** `can:` entry.
  - Public routes → no auth entry at all.
- Output: `OK <n> routes checked` or a list of failures. Exit 1 on any failure.

- [ ] **Step 1:** Write the checker, plus a tiny self-test (`php check-routes.php --self-test`) that runs it on an inline fixture with one match, one miss and one wrong-middleware entry, and asserts the outputs.
- [ ] **Step 2:** Run `run.sh` for both apps; route checks pass.
- [ ] **Step 3:** Commit `test: check benchmark routes and middleware against route:list`.
