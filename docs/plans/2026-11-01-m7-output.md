# M7 — Output & CI features Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `analyze` output usable in a terminal and in CI. That means a readable console report, JSON, SARIF 2.1.0 for code-scanning tools, baseline files, `--since` for changed-code-only runs, and `--strict` for CI.

**Architecture:**
- Three formatters render an `AnalysisResult`: `ConsoleFormatter`, `JsonFormatter` and `SarifFormatter`. `AnalyzeCommand` picks one with `--format` and writes it to stdout, or to `--output` with the summary going to stderr.
- `BaselineFile` reads and writes the fingerprint file used by `--baseline` and `--generate-baseline`.
- `ChangedFiles` (git through `symfony/process`) and `ImpactAnalyzer` narrow the payloads for `--since` before `Engine::run`.

**Tech Stack:** PHP ^8.2, symfony/console, symfony/process (new), opis/json-schema (already present, used for SARIF validation in tests).

**Spec:** `docs/SPEC.md` §11, §12 (`--since`), §13 and §14. Roadmap tasks 38–42, plus the decisions below.

## Decisions

1. **`--strict` (user, 2026-11-01).** It's opt-in, with the default unchanged. With `--strict`, if any sent request ended `failed`, `refused`, `invalid` or `truncated`, or any payload was `unsent`, the run exits 2. Precedence: **1 beats strict-2, which beats 3.** Failing findings are the more useful CI signal, and both fail the build. The summary names the strict reason.
2. **`--generate-baseline` captures every current finding.**
   - It includes non-failing findings and those below `--level`. To make that possible, the Engine keeps below-level findings in `AnalysisResult::$filtered` instead of discarding them.
   - Suppressed findings are excluded; they're already silenced by comments.
   - It writes the file and exits 0, whatever the findings.
3. **Baseline file format.** The file is `semantic-sec-baseline.json`:
   ```json
   {"version": 1, "tool": "semantic-sec",
    "fingerprints": [{"fingerprint": "…", "category": "idor", "file": "…", "symbol": "…", "title": "…"}]}
   ```
   It's sorted by fingerprint and pretty-printed, so diffs are reviewable. Loading reads only the `fingerprint` values. A missing default file means an empty baseline. A missing `--baseline` path, bad JSON or the wrong `version` is exit 2. Writes go through a root-confined safe writer: no symlinks, no escaping the root, atomic.
4. **`--since=<ref>`** runs `git -C <root> diff --name-only <ref>...HEAD` through `symfony/process`, with array arguments and no shell.
   - A ref that starts with `-` or contains whitespace or NUL is rejected with exit 2. So is a project root that isn't a git repo, and an unknown ref.
   - Only committed changes count; this is documented.
   - The `ImpactAnalyzer` rules come from SPEC §12.
   - Candidates that aren't affected are not sent. Their count goes into a new stat, `unaffected`, and the identity becomes `payloads = skipped + unaffected + unsent + cacheHits + sent`.
5. **Output text safety.**
   - Console output escapes every model-controlled or source-derived string with the existing `Terminal` helper.
   - JSON and SARIF are structured encodings: no console escaping, but control characters are stripped from model text the same way.
   - **Fingerprints, cache keys and file paths are never passed through the `Redactor`.**
6. **`--output <path>`** writes the formatter output to that file (via the safe writer) and prints the summary to stderr.
   - Without `--output`, `console` prints everything to stdout. `json` and `sarif` print only the document to stdout and send the summary and warnings to stderr, so the stdout stays parseable.
   - `--output` is relative to the cwd, like any CLI path. It may point outside the project root, because it's the user's own choice, but it must not be a symlink.

## Global Constraints

- PHP `^8.2`. CI runs 8.2, 8.3 and 8.4 at the lowest and highest dependency versions. Add `symfony/process: ^6.4 || ^7.0`, matching the other symfony constraints, and never disable Composer security-advisory blocking.
- There is no host PHP: run everything through `docker compose run --rm php <cmd>`.
- The default suite makes zero LLM calls. **Never open `.env.live`.** Use FakeClient, or the pinned benchmark cassette replay, for end-to-end output tests.
- Never edit `benchmark/`; copy it to temp dirs. Real apps are read-only.
- A false drop or exclusion hides a vulnerability. Formatters must render every reported finding, nothing silently omitted.
- One-line comments only. Commit as Tushar Khan with no AI trailer. One branch, `m7-output`, and one PR into `main`.

## Review Focus

1. **SARIF accepted by GitHub code scanning.** It must validate against the vendored official 2.1.0 schema.
   - `partialFingerprints` stable.
   - Relative URIs with `uriBaseId`.
   - `startLine` ≥ 1.
   - No `fixes` (superseded in Task 4: the patch goes in `properties.patch`).
   - An empty-findings run is still valid SARIF.

   Task 4 covers this.
2. **Baseline round-trip.** Generate, then analyze again with `--baseline`, gives 0 reported and N baselined. A changed finding re-appears. Task 5 covers this.
3. **`--since` blast radius.** A change to middleware, a policy, a FormRequest, a model or a global file must widen the set as SPEC §12 says. A change outside every path must send nothing and exit 0. A bad ref is exit 2. Task 6 covers this.
4. **Hostile text in output.** Titles or paths containing ANSI codes, console tags, newlines, `</script>`, or JSON/SARIF-breaking characters must render inert. The JSON and SARIF documents must still parse. Tasks 2–4 cover this.
5. **`--strict` precedence** with findings, budget and failures combined. Task 1 covers this.

  - All text goes through `Terminal`.
- `SafeWriter::write(string $path, string $contents): void` throws a `RuntimeException`, which `AnalyzeCommand` turns into exit 2.

### Task 4: `SarifFormatter`

**Files:** create `src/Output/SarifFormatter.php` and `tests/Fixtures/sarif-schema-2.1.0.json`, vendored from the official OASIS repository with its source URL recorded in a sibling `.source` file. Modify `AnalyzeCommand` (`--format sarif`). Test: `tests/Unit/Output/SarifFormatterTest.php`.

**Interfaces:** SPEC §14.
- **Rules:** one per category present, or all five if that's simpler. `id` is `CWE-xxx`, plus `name`, `shortDescription` and `helpUri` (`https://cwe.mitre.org/data/definitions/<n>.html`).
- **Results:** each has:
  - `ruleId` and `level` (critical/high → `error`, medium → `warning`, low → `note`)
  - `message.text` (title plus flaw)
  - `locations[0].physicalLocation.artifactLocation` with `{uri, uriBaseId: "%SRCROOT%"}` and `region.startLine`
  - `partialFingerprints: {"semanticSec/v1": <fingerprint>}`
  - `properties: {confidence, failing, category, symbol}`
  - `codeFlows[0].threadFlows[0].locations` built from `path`, when the path isn't empty
  - `fixes`, only when `patch !== ""`: put the unified diff in `description.text`. `artifactChanges` needs exact regions, which a unified diff doesn't give reliably, so describe the fix instead and note it in SPEC.
- Suppressed findings appear as results with `suppressions: [{kind: "inSource", justification: reason}]`. Baselined findings appear with `baselineState: "unchanged"`.
- `run.tool.driver` has `name`, `version`, `informationUri` and `rules`. Set `originalUriBaseIds.%SRCROOT%`.

**Interfaces:**
- `ChangedFiles::between(string $root, string $ref): list<string>` returns root-relative paths and throws `RuntimeException` on a bad ref, on a non-repo, or when git is missing.
- `ImpactAnalyzer(ParseResult, SymbolTable, Config)` exposes `affected(list<Candidate> $candidates, list<string> $changed): list<Candidate>`. A candidate is affected when one of these holds:
  - any node of its execution path is in a changed file
  - its route file changed
  - a middleware, policy, FormRequest or model it uses is in a changed file
  - `app/Http/Kernel.php`, `bootstrap/app.php` or any `*AuthServiceProvider.php` / `*RouteServiceProvider.php` changed, in which case every candidate is affected
- Payloads of unaffected candidates aren't sent; they're counted in `unaffected`.
